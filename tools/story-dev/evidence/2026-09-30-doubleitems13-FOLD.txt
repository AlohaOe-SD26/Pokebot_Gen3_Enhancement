### 4. New log lines (the debug logger writes `[CATEGORY] message`)
All examples below are real output from the gate.

**`[DBLITEM-OBS]`** (observe only, one per decision):
- Format: `side= g= turn= me=<Species>#<PID8 upper> P= hp=cur/max would=<Item_With_Underscores|-> why= key=<1|0|?> worst= uses= bpo=<6 hex> bpo_pos=<0|1|tailN|?> disc=<0|1> cur=<8 hex>`
- `why` takes one of: hp, cure, not_key, ineffective, fainted, cap, above_fraction, no_hp_item, losing_race, declined.
- If the battler is missing, the line is `side= g= turn= me=- would=- why=no_mon`. On an internal error it is `side= g= err=<Type>: <msg>`.
- Example: `[DBLITEM-OBS] side=1 g=2 turn=3 me=Mightyena#5C96EA9B P=4 hp=20/100 would=Potion why=hp key=1 worst=0 uses=0 bpo=140235 bpo_pos=1 disc=1 cur=00000100`

**`[DBLITEM] use`** (flag 1, when the strategy acts; the item name keeps its spaces):
- Example: `[DBLITEM] use side=1 g=2 item=Potion target=Mightyena#5C96EA9B P=4 hp=20/100 self=1`

**`[DBLITEM] menu`**:
- The design's fields come first, contiguous, as the predictions quote them. Then `aim=` (the slot the bot drove at, next to the actual `slot=`), `self=`, and `err=` only when a guard read failed.
- Pass: `[DBLITEM] menu g=2 battler_in_menu=2 layout=1 slot=1 menu_pid=5C96EA9B intended_pid=5C96EA9B ok=1 a_pressed=1 aim=1 self=1`

**Guard refused.** There is no separate "guard refused" line: a refusal is the `menu` line with `ok=0 a_pressed=0`.
- PID mismatch: `[DBLITEM] menu g=2 battler_in_menu=2 layout=1 slot=1 menu_pid=0B30A747 intended_pid=5C96EA9B ok=0 a_pressed=0 aim=1 self=1`
- Out of range: `... slot=7 menu_pid=- intended_pid=5C96EA9B ok=0 a_pressed=0 aim=1 self=1`
- Read failure: `[DBLITEM] menu g=2 battler_in_menu=? layout=? slot=? menu_pid=- intended_pid=5C96EA9B ok=0 a_pressed=0 aim=1 self=1 err=RuntimeError`
- The NOGUARD shape is `ok=0 a_pressed=1`.

**`[DBLITEM] after`** (target and partner are both `Species#PID`; `same=1` means the target's PID at that party index did not change between the two reads):
- Example: `[DBLITEM] after g=2 target=Mightyena#5C96EA9B hp=30->50 status1=0->0 partner=Sceptile#863B0917 hp=40->40 Potion=1->0 healed=0->1 same=1`

- `[DBLITEM] struggle-exit g=0 — battler 2's action menu is open; no A pressed into it (D11)` when D11 fires.

### 6. Decisions the spec did not settle (for the decisions log)
1. **NOGUARD** skips only the PID comparison. The range check and the self binding still hold. So `ok` is logged honestly as 0 while `a_pressed=1`.
2. **A failed self binding** makes the guard refuse at the party menu (`self=0 ok=0`). It does not abort before the bag opens.
3. **Menu-open precondition (my addition):** the guard refuses unless the game state is PARTY_MENU when it reads. A stale `slotId` could otherwise match the intended PID in field order and send A into the bag. Pinned by DBmenuclosed and mutant MB17.
4. **Flag tests:** the executor tests the flag inline (`== "1"`, the same rule as `mode()`) and imports `double_items` lazily on the flag-on path, so core code never depends on a story module when the flag is off. The strategy uses `double_items.mode()`.
5. **Ledger key** is (PID, species index), following `faint_chooser`'s identity convention rather than the species name.
6. **Observe's key field:** `key=` comes from `key_battle_verdict(True, sides)` (1 = key class, 0 = every side read and none key, ? = unreadable). `would=` applies KEYITEMS through `key_battle_verdict(KEYITEMS=="1", sides)` and fails open.
7. **Observe's cure policy** gets the HP options (D10) and a constant party count, since `allow_revive=False` never reads the count.
8. **D10's mechanism** is a `medicine` rebind before the cure call, because `repro_battle_items.py` pins the call's own text.
9. **Index spaces in the executor:** it receives the battler id g (0 or 2) and derives side = g // 2 and partner = g ^ 2. The `after` line's partner is `gBattlerPartyIndexes[g^2]`.
10. **Line format additions:** the `menu` line gets `aim=` and `self=` at the end; the `after` line gets `same=`; there are the `err` and `struggle-exit` lines; `bpo_pos` prints `tailN` when the requester sits outside positions 0-1.
11. **The fail-open path logs a line.** D9 says only "an exception gives the parent's attack"; I added the `err` line so the fallback is visible.
