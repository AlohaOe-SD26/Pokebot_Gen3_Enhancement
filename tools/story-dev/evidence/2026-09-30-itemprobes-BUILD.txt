### Bug found and fixed (in my own new code)
- **The problem:** the `[DBLITEM] after` label pattern was `.+?#[0-9A-F]{8}`, tried before `\?`. When the target can't be read, the emitter (`battle_action_selection._dbl_after`, `t0` None) prints `target=? hp=?->117 …`. The lazy pattern then ran on into the partner's `Species#PID`, so the partner's HP change (e.g. 18->109) was bound to the target.
- **Fix:** both labels are now `[^=]+?`; a label can't contain `=`, so it can't cross into the next field.
- **Effect:** only `target_hp` was wrong. No count the probes report uses it today, and I2-I4 outputs are byte-identical after the fix.
- **Pinned:** row DB13, and M77, which reverts the fix and turns exactly DB13 red.

### Decisions the spec did not settle
1. **WILD needs `[TRAINER]` lines somewhere in the log.** D2 literally says "WILD = a started battle with no `[TRAINER] start`". In a log written before `[TRAINER]` existed, that would call every trainer battle WILD. So a battle is WILD only if its log contains at least one `[TRAINER]` line; otherwise it is UNCLASSIFIED. Under D2's literal rule I2 would have failed ("every item battle UNCLASSIFIED"); I1 allowed either. Mutant M20 pins this.
2. **KEY / NON-KEY rule.** KEY if any side's class id is a key class, matching production's `key_battle_verdict`. NON-KEY only if every side was read and none is key. An unreadable side next to a non-key one gives UNCLASSIFIED.
   - Classes come from both `[TRAINER] start` and `end` lines, so a battle with only an end line still gets a class.
   - A battle whose only `[TRAINER]` lines are `skip` or `unreadable` is UNCLASSIFIED.
3. **Lines before a log's first `[BATTLE] started`** form their own record, which is always UNCLASSIFIED, so no line is ever dropped.
4. **A fourth legacy `[ITEM]` kind from git history (706d6b4c):** `‼ no effect … — item use is not executing; disabling …`, now `legacy_not_executing`.
5. **A shared line shape.** `‼ no effect … — retrying with the X-order index` was the legacy index flip, and today's code still prints the same text when the bag count can't be read. It always counts as no-effect. The legacy verdict switches on only when a legacy-only line (`legacy_landed`, `legacy_both_failed`) exists. Today's unreadable-bag disable line is its own kind, `no_effect_disable`.
6. **Exit code 1 (control failures):**
   - Both probes: no logs; any stray tag mention.
   - Boss probe: no turn parsed; any `[TURN]` line with foe data that didn't parse.
   - Item probe: no `[ITEM]` and no `[DBLITEM]` lines; requests but no verdict line of any kind (this replaces the old "NO LANDING RECORDS" guard); any unknown kind.
   - A `[KEYBATTLE]` disagreement is printed as a finding and does not fail the run.
7. **Line matching and controls:**
   - Lines are matched by category position, `^(?:f\d+ )?\[CAT\] `; a "stray" control counts any tag mention outside that position (0 in the corpus).
   - Species names are matched with `.+?`, because `species.json` has `Nidoran♀` and `Farfetch’d` (typographic apostrophe), which the old ASCII pattern missed.
8. **Outcomes:** taken from `[BATTLE] ended (outcome=…)`, falling back to `[TRAINER] end res=`. Anything else counts as other: RanAway, Caught, Teleported, Draw, or a log that ends mid-battle.
9. **CLI:**
   - The default `--profiles` is the main checkout's, found through the worktree's `.git` file.
   - `--profiles` requires `--since/--until`.
   - A stamp, `--since/--until` and `--logs` are mutually exclusive.
   - `--until` defaults to `--since` and vice versa.
   - The default stamps are unchanged.
10. **Gate fixtures:** whole-battle fixtures are read from committed evidence by line range rather than pasted in. Single lines are pasted verbatim with file:line comments and checked by PROVENANCE.

### Decisions the spec did not settle
1. **NO DATA exits 1 only when there is no `[ITEM]`, no `[DBLITEM]` AND no `[KEYBATTLE]` line.** A refusals-only log is data and exits 0; the tables always print first.
2. **The lost-item column excludes partner-rise lines.** Those are already wrong targets, so it would double-count them. Any unreadable field means "not counted".
3. **Rest = a rise whose record newly gains Sleep** (also inside a combined status like `Sleep/Confused`), at ANY size, not only LARGE. Rest heals to full, so a small rise with new Sleep is also Rest.
4. **`key_group` with sides in different groups reports the first group in order.** None has been seen; Maxie + Tabitha at the Space Center are both magma_aqua.
5. **Attempts are keyed by (log, `opp` string)** from the first `[TRAINER]` start/end line, or `?` if unreadable. "Other" outcomes count as attempts. The median of an even count is the upper middle value.
6. **Heal stock counts HP items (`parameter > 0`), not every healing item.** Unknown item names are listed, not counted. Note the item data gives Energy Root `parameter` 0, so it is not counted as an HP item.
7. **The CLI warns when only `--since` or only `--until` is given.** `--profiles` and `--lanes` require `--since`/`--until`. `--lanes` is a substring match on the lane name and is repeatable.
8. **win_rate excludes "other"** (a battle the log never finished) and is "n/a", never 0%, when nothing was decided.
