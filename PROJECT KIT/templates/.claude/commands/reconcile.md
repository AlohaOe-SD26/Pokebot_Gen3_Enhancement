Reconcile this project's PRE-EXISTING instructions with the Project Kit's standing directives. Run once after bootstrapping a project that already had its own CLAUDE.md, agent instructions, or session protocol. Golden rules: ASK before changing anything; NOTHING is deleted without explicit approval; never edit inside the managed PROJECT-KIT DIRECTIVES block (that belongs to Bootstrap-Project).

1. Read everything: `CLAUDE.md` in full (inside AND outside the managed block), any other agent-instruction files (AGENTS.md, .claude/ files, agent-addressed README sections), and `PROJECT KNOWLEDGE/00-README.md` + `04-HANDOFF.md` for the project's conventions.
2. Classify every instruction found OUTSIDE the managed block:
   - **PROJECT-SPECIFIC rules** (tech constraints, test suites/gates, save-format versioning, style rules, domain invariants): KEEP untouched. These compose with the kit directives and always remain in force.
   - **OVERLAPPING session protocol** (its own "read the handoff first", wrap-up / resume command words, commit-and-push discipline): propose deduplication — the managed block becomes the single source for session protocol, and the older wording is removed or rewritten as a short pointer to it. Any project-specific detail the kit block LACKS (e.g., "verification = suite + determinism gate") is preserved by moving it to a clearly-headed "Project-specific protocol additions" section outside the block.
   - **CONTRADICTIONS** (rules that directly conflict with the managed block — e.g., "batch commits weekly" vs per-item push): list each conflict side by side with consequences, and ASK the user which side wins. NEVER silently follow either.
3. Present the complete plan as a diff-style summary — keep / move / rewrite / remove, each with a one-line reason — and wait for approval.
4. Apply ONLY what was approved. Back up first: copy CLAUDE.md to `CLAUDE.md.pre-reconcile` (and likewise any other file edited).
5. **Retire stale prevention rules:** scan `08-MISTAKES.md` and any "don't do X" lines in the project's own instructions. For each, check whether the underlying mistake is now structurally impossible (a test, lint rule, type, or refactor now prevents it). A standing "never do X" line keeps that idea active in every future context and wastes tokens, so for each rule that is now safe to drop, propose retiring it (note the retirement in `08-MISTAKES.md` under the entry's "Retire when"). ASK before removing any rule.
6. Finish per the definition of done: changelog entry, handoff note, commit (`docs: reconcile project directives with Project Kit`), push, and report what changed (created vs appended vs updated vs removed) with the push confirmed.
