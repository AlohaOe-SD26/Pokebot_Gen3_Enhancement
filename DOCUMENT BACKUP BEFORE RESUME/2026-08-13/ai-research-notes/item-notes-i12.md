Here are the ROM-accurate facts about the Pickup ability in Pokémon Emerald.

### 1. Core Mechanics

*   **Activation Condition:** (VERIFIED) The Pickup check occurs after any battle that awards experience points or prize money. This includes both wild Pokémon and Trainer battles. It does not trigger after fleeing a battle.
*   **Activation Trigger:** (VERIFIED) The check is performed for every Pokémon in the player's party with the `ABILITY_PICKUP` that is not currently holding an item.
*   **Participation Requirement:** (VERIFIED) The Pokémon with Pickup does **not** need to have participated in the battle. The check is performed on all eligible party members.
*   **Probability:** (VERIFIED) For each eligible Pokémon, there is a **10%** chance for the ability to activate after a battle.
*   **Source Code:**
    *   The post-battle check is initiated in `src/main.c`, in a function often named `DoSoftReset` or `CB2_NewGame` in a context that handles returning from a battle. It calls a function (`sub_801A72C` in some decompilation builds) that contains the loop for post-battle ability effects.
    *   This loop calls `DoPickup` for party members. The core probability check within `DoPickup` is `if ((Random() % 100) < 10)`.
    *   The function that determines the specific item received is `GetPickupItem` in `src/item.c`.

### 2. Item & Level Table

(VERIFIED) The item generated by Pickup is determined by the Pokémon's level. The game generates a random number from 0 to 99. This number is used to select an item from a specific "sub-table" based on commonality. The final two slots (corresponding to a roll of 98 or 99) contain rare items that change based on the Pokémon's level.

Emerald's Pickup table is a significant upgrade from Ruby & Sapphire's.

**Source Code:** `const u16 gPickupItemTable[]` in `src/item.c`. The logic for selecting an item from this table based on level is in the function `GetPickupItem(u8 level)` in the same file.
