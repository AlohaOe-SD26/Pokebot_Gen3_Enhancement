## 1. What each ruling requires in code

**RULING 24 (catch while hurt or training).**
- **Pre-gym-1 needs no gate change.** Its branch returns before both refusals (`story_mode.py:1912-1917`), so team building already catches while hurt and during `train_team`.
- **After gym 1, remove two refusals and nothing else:** `training` (`:1952-1958`) and `party_healthy` (`:1963-1970`). Every other gate stays: runway, hunt-armed, hunt-walking, reserve, PC full, attempts, expected throws and resource block.
- **Three companion changes are also required:**
  - **Survival mode must stop fleeing a wanted species.** It runs before the dex branch (`:3996-4023` vs `:4029`), so today a wanted species is fled on any map with 3 or more defeats.
  - **A catch started during training must not rotate the lead.** The catch classes inherit `DefaultBattleStrategy.choose_new_lead_after_battle` (`default.py:211-217`), and the listener acts on it (`_listeners.py:237-241`). `train_team` computes `need` by slot (`early_game.py:2385-2402`). A rotation therefore reproduces the KI-84 early exit in the `slots={0}` grinds: counter training, the §Ch23 chunk (which can raise "banked NO EXP", `victory_road.py:2468`) and the §Ch24 rung.
  - **Post-gym-1 dex-catch losses must not count as map defeats.** They feed survival mode and the boss counters (`:2322-2340`), including the Route 110 rival, whose `keys=[ROUTE110]` (`:4969`). This applies to kind `dex` ONLY. Pre-gym-1 `team` catches (`:4077`, `"dex" if _post_badge else "team"`) keep today's accounting, because that branch "must stay behaviourally identical" (`:1909-1911`, `#24-partycap`). `[C15]`
- **By 06's reading, the bot should also stop fleeing on the first faint.** That bail has TWO paths, and both must change. `[C5]`
  - `should_flee_after_faint` (`:128-139`).
  - `decide_turn` (`:165-185`). It calls `dex_catch_bail_reason(spare, reserve, self._fainted_this_battle)` (`:172-173`), which returns "a team member fainted" whenever that attribute is True (`:105-106`). The attribute is set at `:133`, before any escape check.

**RULING 23 (money for balls).**
- **Add a restock at the dex reserve.** Today a restock fires only at 1 ball or fewer, from three call sites (`early_game.py:2827-2833`, `:5189-5192`, `counter_hunt.py:542-546`), and only at Rustboro (`early_game.py:2513-2517`). Nothing restocks at the reserve of 10 (`story_mode.py:1959`).
- **Make it a pure, bounded budget function:**
  - Poké Balls only.
  - It stops at badge 7 and in the early-basket era.
  - Its floor is never below `league_reserve.CASH_FLOOR`, so RULING 18's basket and its ₽1,000 reserve are untouched.
- **A separate defect:** the counter ladder's own restock is dead code, because `resource_blocker()` refuses at `:2893` before `hunt()` could restock at `:2925`.
- **Money-making is plan-only** (section 4).

**RULING 25 (the cap).**
- **Raise the per-species, per-run cap from 2 to 3** (`:1646`, read only at `:1971`).
- **Exempt rare and legendary species.** Shiny needs no change: the shiny branch never reads the cap (`:3812-3832`). "Rare" needs a classifier derived from the ROM tables.
- **Add a real per-species terminator for uncapped species.** `[C7]` RULING 24 accepts whiteouts, and the attempts gate is today's only per-species terminator (`:1971`). The code says so itself: "ATTEMPTS IS THE ONLY COUNT THAT TERMINATES" (`:2248-2253`). A rare species without a ceiling could therefore loop through whiteouts, faint-bails, reserve bails, flees and Teleports alike.
  - A bound that counts only `Lost` endings would not terminate. With step 5 off, a faint ends `RanAway` (a faint bail), and Abra ends `OpponentTeleported`.
  - So the terminator counts EVERY attempt, whatever its ending (step 8). This is a cap by another name, and RULING 25 said "uncapped", so the number goes to the user (Q5).
- **Two facts limit the effect:**
  - The cap has never been the deciding refusal: 0 "already attempted" lines in 184 logs.
  - The expected-throws gate (`:1979`) still refuses 10 of the 30 rare species the bot meets. "No cap" alone therefore changes little until the user rules on that gate (Q4).

### Step 1 (NEW, OPTIONAL — LOW PRIORITY): throw first against a foe that can only Teleport (the Abra finding) `[C22]`
⚠ **Build this LAST, or not at all, until a fixture exists.** The mechanism is real, but it has NEVER FIRED: across every
`[TURN n] … vs Abra` line in `sandbox-pokebot/profiles/**`, no sleep or paralysis move was ever used against an Abra, so
the bot already throws on turn 1 in every observed case. The P2-c Abras escaped because ~0.28-chance throws MISSED (an
earlier claim in the session that the status-move logic caused those escapes was WRONG). **The real first build is step 2.**
Small and independent of the rulings.
- **The mechanism (decomp, via the second checker):**
  - A bag item (a ball) always acts before any move: `SetActionsAndBattlersTurnOrder` queues `B_ACTION_USE_ITEM` ahead of every move (`battle_main.c:4817-4826`).
  - A wild Abra knows only Teleport (`species.json` level_up = {Teleport: 1}; `level_up_learnsets.h`).
  - Teleport fails only in a trainer battle or when the user cannot escape (`battle_scripts_1.s:1925-1932`).
  - So a throw on turn 1 guarantees exactly one throw. A status move on turn 1 gets zero throws whenever Abra (base Speed 90) moves first.
- **Where the decision lives:** `sandbox-pokebot/modules/battle_strategies/catch.py:50-62` (`CatchStrategy.decide_turn`).
  - When the foe is Healthy and `calculate_catch_success_chance` (`_util.py:271-294`) is below 0.5, it returns the move from `_get_best_status_changing_move` (`catch.py:186-210`: SLEEP or PARALYZE only), if the active mon has one, before it ever throws.
  - Abra at full HP (odds 66), by `_util.py`'s formula (synthesis arithmetic; the checker's decomp recompute agrees on 0.2797):
    - Poké Ball: 0.28;
    - Great Ball: 0.41;
    - Ultra Ball: 0.62, so it already throws first.
- **Measured scope. The risk is REAL but LATENT.** The status-first path fires only when the ACTIVE mon holds a SLEEP or PARALYZE move.
  - **The logs:** across every debug log under `sandbox-pokebot/profiles/`, the `[BATTLE] [TURN n] … vs Abra` lines (`battle_action_selection.py:535`) show NO sleep or paralysis move used against an Abra on any turn.
    - 38 distinct moves were used against Abra. None has effect SLEEP or PARALYZE in `moves.json`.
    - Turn-0 actions against Abra include 515 `UseItem` lines. These are line counts; rotated copies in `Old/` may duplicate them.
  - **The P2-c evidence** (`tools/story-dev/evidence/2026-09-28-r20P2c-X2-OFF-s1.txt`, three Abra team catches at f140752, f142577 and f144228, all escaped) **is NOT an instance of this risk.**
    - The party is Mudkip, Poochyena, Nincada and Whismur. None of them learns a SLEEP or PARALYZE move by level-up at L25 or below (`species.json`).
    - So `_get_best_status_changing_move` returns None, and the OFF thrower already throws on turn 1.
    - The three escapes read as three failed ~0.28 throws, each followed by Teleport (0.72³ ≈ 0.37 for all three).
    - Caveat: the huntfirst driver left no debug log; its evidence file records only the strategy class and fence reason per battle. So turn 1 there is INFERRED from code plus learnsets, not observed. The party's actual movesets were not read from the save; a TM move would change this, but none is expected before gym 1.
  - **Who can trigger it,** as the active mon when an Abra appears (`species.json`, learned by L20):
    - Electrike (Thunder Wave, L4);
    - Shroomish and Breloom (Stun Spore, L7);
    - Skitty (Sing, L13);
    - Jigglypuff (Sing, L1);

- **Flag:** `POKEBOT_R25_THROWFIRST`, default OFF. It is read per run and handed to the strategy at construction; the strategy's own default is OFF.
- **The change:**
  - Add a pure `throw_first_reason(foe_move_effects) -> str | None`. It returns "foe can only Teleport" when the foe's known, non-empty move slots form a non-empty list and every effect is `TELEPORT`. It returns None otherwise, and None on any unreadable input, which falls back to today's behaviour.
  - In `StoryCatchStrategy.decide_turn` (`story_mode.py:85-93`), under the flag, after the out-of-balls check and before `super().decide_turn`: if the reason is not None, return `TurnAction.use_item(<best ball>)`.
  - **Do not edit `catch.py`.** It is upstream-derived and shared by non-story modes.
  - **The order is preserved.** `StoryDexCatchStrategy.decide_turn` checks its bails first (`:165-184`) and only then calls `super()`, so the reserve and faint bails still win.
