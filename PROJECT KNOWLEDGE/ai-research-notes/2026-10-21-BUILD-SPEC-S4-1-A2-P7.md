## Why

- Today the AI player's 17 unit suites run SERIALLY through `ai_player/gates/run_units.py`: 6 m 13 s quiet, 9 m 28 s
  busy. `test_check_purity` alone is 265-382 s of that: 157 planted probes at about 1.7 s each.
- The six revert drivers run by hand, one by one. Nothing chains them; on 2026-10-16 they were chained by a script that
  is not in the tree.
- A builder or verifier then reads raw logs to learn the verdict. A2's aim is that it reads a 2-4 KB summary instead,
  and calls an agent only on a failure.
- The verdict vocabulary is only PASS/FAIL. A unittest `OK (skipped=N)` passes silently, and a suite that ran zero
  tests would read PASS.
- `tools/workflows/regression_due.py` can never say `ok`: no evidence producer records a scope as wide as a suite's
  `covers`. A runner that records exactly that scope is the remedy its own docstring names.

## What to build

### 1. `ai_player/gates/run_regression.py` (TEST SIDE; new)

- `py -3.12 ai_player/gates/run_regression.py [--quick | --full] [--workers N] [--evidence] [--only NAME ...] [--list]`.
- **No ROM, no emulator, never graded.** It never runs a `rate_*` or `live_*` driver, and never writes the seed
  ledger. Those suites appear in its summary as `NOT-RUN` with the reason ("graded / needs the ROM: run it
  deliberately").
- **`--quick`** (the per-edit lane, target <= 25 s wall): the 13 fast units, run in parallel, from the recon's Q3(c)
  list. check_purity, test_eyes, test_hands, test_battle, test_evidence, extract_knowledge `--check`, test_goals,
  extract_milestones `--check`, ledger `--check`, call_census, check_fairness, check_lessons, disk_budget. Prints the
  summary, and writes evidence only with `--evidence`.
- **`--full`** (the default; every commit's gate, run in the background):
  - all 17 units, with `test_check_purity` SHARDED by test method (below);
  - and the six revert drivers: revert_step11, revert_step2, revert_step3, revert_step4, revert_step5,
    revert_safety_gates.
  - All run in parallel up to `--workers` (default 6). The bot tuner holds 12 lanes on this 32-thread PC, so do not
    default higher. revert_step3 (about 2,014 s) sets the wall floor: start it FIRST.
- **Sharding test_check_purity:** plan the shards from the module's own test method names (AST, never a typed list),
  balanced by a measured per-method time table kept in a small JSON beside the runner. Shards are run as
  `py -3.12 -m unittest -k <method> ...` or an equivalent that names each method exactly once.
  - FAULT: a planner that drops or duplicates a method fails a test.
  - The ROUND3 method (about 73 s) is the floor; splitting its subTests is OUT of scope.
- **Per-suite timeout** (default 3,600 s; revert_step3 gets 2.5x its measured time). On timeout, kill the whole process
  tree (Windows: `taskkill /T /F /PID`) and record `TIMEOUT`.
- **The frozen tree** (rule G1, `provenance.FrozenTree` or the same digest run_units uses): the tree digest is taken
  before the run and checked after EVERY suite. A change during the run makes the run `FAIL` ("the tree changed
  mid-run"), as run_units already does.
- **Refuse to start (exit 2, nothing written)** while a `rate_*.py` or `live_*.py` driver process is running.
  - Find them by command line (`Get-CimInstance Win32_Process` through `powershell -NoProfile`, or the stdlib
    equivalent). Make the probe injectable for tests.
  - Why: test_safety_gates compares the ledger's bytes before and after (recon Q3(d)), and a running sweep writes it,
    so a parallel run would fail spuriously or race on `trees/<digest>.zip`.

### 2. The typed verdict and the summary (N8's runner half)

- Each suite ends in exactly one status:
  - `PASS`
  - `FAIL` (non-zero exit, a `FAILED`/`NOT CAUGHT`/`PREDICTION WRONG`/`NO RESULT`/failing `CONTROL` line, or the tree
    changed)
  - `VACUOUS` (exit 0 but `Ran 0 tests`, or a revert driver that reports zero mutants)
  - `TIMEOUT`, `CRASH` (could not start, or a traceback with no verdict line)
  - `NOT-RUN` (graded or ROM suites; a suite skipped by `--only`).
- `PASS` with `skipped=N > 0` stays PASS, but `skipped` is recorded, and the printed line says `PASS (N skipped)`.
- Parse only the verdict lines the recon quotes (Q1: `OVERALL:`, `VERDICT:`, unittest `Ran N tests` / `OK` / `FAILED`,
  the revert words). Unknown output with exit 0 and no recognised verdict line is `CRASH`, never PASS.
  - Print each compiled regex and test it on a positive and a negative list (the real tails in the recon are the
    positives).
- **`<evidence>.summary.json`**, at most 4 KB, enforced by truncating lists with a count:
  - `{"schema": 1, "lane", "started", "wall_s", "code_line", "overall", "suites": [{"name", "status", "exit",
    "seconds", "tests", "skipped", "failing": [first 3 lines], "shards"}]}`;
  - `overall` is PASS only if every RUN suite is PASS;
  - `NOT-RUN` never makes it FAIL, but it is listed.
- **Console:** one line per suite (status, name, seconds, the key count), then `REGRESSION: <OVERALL> (<lane>, <n>
  suites, <wall> s wall)`, then the evidence and summary paths. Exit codes:
  - 0 PASS;
  - 1 FAIL / VACUOUS / TIMEOUT / CRASH;
  - 2 refused;
  - (distinct and pinned by a test).

### 3. Evidence files that `regression_due.py` recognises, with a scope it can check (the PR-2 remedy)

- With `--evidence`, or always on `--full`, write one evidence file per suite_map suite the run covered, named to match
  `tools/workflows/suite_map.json`'s globs:
  - `<date>-regression-units.txt` (glob `*-units.txt`);
  - `<date>-regression-step5-revert.txt` (`*-step5*-revert.txt`);
  - `<date>-regression-revert-gates.txt` (`*-revert-gates.txt`).
  - The other reverts go into the units file's appendix, or into their own files if you add them to suite_map (your
    call; say which).
- Each file holds the provenance code line and the raw output of its suites, in sections. Its `.summary.json` sits
  beside it.
- Use `provenance.keep_earlier` exactly as run_units does, so a same-day re-run archives the earlier file. Fix
  keep_earlier so it ALSO moves the sibling `<stem>.summary.json` (recon Q2).
- **The new scope label:** the code line records `covers:<suite>`. Its digest is computed over that suite's `covers`
  + `reads` minus `exclude`, exactly the files regression_due checks. Add `covers:<suite>` to regression_due's
  `LABEL_SCOPES` handling: one function computes the digest, and both tools call it.
  - Acceptance: after a real `--full` run on a clean tree, `regression_due.py` prints `ok` for units, revert_step5
    and revert_safety_gates.
  - FAULT: a one-byte edit to a covered file makes it DUE.
  - CONTROL: an edit to an uncovered file does not.

## Tests (FAULT + CONTROL each; fake suites are tiny scripts in a temp folder, never the real ones)

- **T1 statuses:** one fake suite per status. PASS, FAIL (exit 1), FAIL (exit 0 with a `NOT CAUGHT` line), VACUOUS
  (`Ran 0 tests`), skipped, TIMEOUT (sleeps past a 2 s limit; its child process is killed too), CRASH (exit 0, no
  verdict line). Each gets the right status and exit code, and the overall verdict is right.
- **T2 parallel:** 4 fakes that each sleep 2 s finish in under 5 s with `--workers 4`. CONTROL: `--workers 1` takes at
  least 8 s.
- **T3 the shard planner:** on the REAL test_check_purity module, every method is named exactly once across shards.
  FAULT: a planner that drops one fails. On a synthetic module, a new method lands in some shard with no edit to the
  time table.
- **T4 the frozen tree:** a fake suite that touches a file in a scratch "tree" makes the run FAIL ("tree changed").
  CONTROL: a read-only suite PASSes.
- **T5 refusal:** an injected probe that reports a `rate_step5.py` process -> exit 2, and no evidence or summary is
  written. CONTROL: an empty probe runs.
- **T6 summary:** valid JSON, schema 1, at most 4 KB with 40 failing suites (lists truncated with a count). `overall`
  agrees with the console line.
- **T7 evidence pairing:** keep_earlier and prune_evidence `--retire` move the `.summary.json` with its `.txt`. FAULT:
  the old code leaves it behind.
- **T8 scope:** on a throw-away git repo with a synthetic suite_map, a `covers:<suite>` code line reads `ok` in
  regression_due. A covered edit gives DUE; an uncovered edit stays ok.
- **T9 run_units TIMEOUT:** a fake suite past its timeout is recorded TIMEOUT, and the runner finishes and writes its
  evidence.
- **Mutants:** a call-deleting mutant on a COPY for each guard: the frozen check, the refusal, the VACUOUS rule, the
  CRASH rule, the summary cap and the summary move. Each must be caught.
