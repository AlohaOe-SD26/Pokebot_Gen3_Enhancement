## 4. KI-129 Part B: an edge ping-pong is a ping-pong (the backstop)

### 4.1 The change
1. **Count edges** (`Navigator.run`, `navigator.py:1246-1247`):
   - A change with `how == "connection"` and a direction also records a use under `f"{change.source}|edge:{change.direction}"`. `Transition` carries `direction` for connections (`memory.py:690`).
   - It uses the same `PINGPONG_USES` (3) and "nothing new since the 2nd use" stop (:1298-1302).
   - The stop message reads `stuck: ping-pong: the edge <name> crossed N times ...`, distinct from the warp text that `live_step3.py` parses. Confirm that regex does not match the new text.
2. **Remember both sides** (F9). On an edge stop, `_remember_pingpong` keeps BOTH `source|edge:dir` and `target|edge:OPPOSITE[dir]` (`OPPOSITE` from `world/memory.py`), each as `(stamp, frame)`. Warp entries are unchanged (a stamp only, no expiry).
3. **`Navigator.edge_ponged(memory, tile, frame) -> bool`.** It is a new method, so `ponged_now`'s warp semantics are untouched. It is True when:
   - `self.ponged` is not None;
   - the tile is `memory.outside`;
   - the key `f"{current}|edge:{road_side(memory, tile)}"` is held;
   - the stamp is unchanged;
   - and `frame - ponged_frame < PONG_REST`.

   `PONG_REST = NOVELTY_WINDOW` (3000): an existing constant, not tuned. `story_moved` clears it with the rest.
4. **Honour edges** (`explore.candidates`' `add()`, after `is_excluded`). Drop a target with `exit is None` and an outside tile when `getattr(nav, "edge_ponged", None)` says so, EXCEPT for kind `"route"` (F6: a known way toward the goal is always kept). Stub navs are untouched.
5. **The fallback, specified (F1).** `travel_intent.choose` (`goals.py:769-778`) keeps its existing fallback to `choose_target` when `found` is empty.
   - `choose_target` re-runs `candidates` (so the ponged edge stays dropped) WITHOUT `keeps_going`. It may therefore take a back that `keeps_going` refused, such as an interior with something left, before it would WANDER (`explore.py:499-512`).
   - This is today's behaviour for an empty `found`, NAMED here rather than changed. The warp ping-pong rule (3 uses) bounds it.
   - Applying `keeps_going` inside the fallback was considered and not chosen: it changes a pre-existing path for every empty-`found` case, which is a wider blast radius than KI-129 needs.

### 4.2 Why it is person-fair
- It uses only the AI's own crossings, its own novelty and its own memory. Someone who walked back and forth over the same line for nothing looks elsewhere for a while.
- Constants are existing ones (3 uses, 3000 frames). There is no place, no hidden state and nothing fitted to a grader (B1).
