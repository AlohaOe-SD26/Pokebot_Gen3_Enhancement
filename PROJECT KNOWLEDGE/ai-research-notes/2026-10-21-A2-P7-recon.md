## Q2 What a `<evidence>.summary.json` beside each .txt would do

No reader would see it (READ):
- `provenance.evidence_digests` uses `folder.glob("*.txt")` (l.159). So `check_evidence` (l.253-260) never counts a summary, and a stale summary can never fail `--check-evidence`.
- `regression_due` uses `folder.glob("*.txt")` (l.297).
- test_safety_gates uses `rglob("*.txt")` (l.628).

Where it would cause trouble:
- **prune_evidence `--retire`** uses `EVIDENCE.glob("*.txt")` (l.201). A retired tree's `.txt` moves to the archive but its summary stays at the top level, orphaned (INFERRED).
  - The archive sweep is `ARCHIVE.rglob("*")` (l.208), so it would see archived summaries.
  - The cited rule is `path.name in text or (path.suffix == ".txt" and path.stem in text)` (l.118). A summary therefore counts as cited only when its full file name appears in a document; otherwise it is deleted or packed (l.209-224).
- **`keep_earlier`** moves only the path it is given (l.162-196). When a driver re-runs on a new tree, the old `.txt` is archived but an old summary would just be overwritten. A file without a `code:` line goes to `archive/no-digest/` (l.188).

Unaffected:
- The digest scope leaves the folder out: `EXCLUDED = (":(exclude)ai_player/evidence", ...)` (provenance.py:60). So do the frozen-tree watch (`_WATCH_SKIP_PATHS`, l.271) and regression_due (`DIGEST_EXCLUDED`, l.101).
- disk_budget, check_lessons and ledger.py do not glob the evidence folder.

Git: `git check-ignore` on a sample `.summary.json` exits 1, so it would not be ignored (MEASURED). The folder holds 209 `.txt` files plus `archive/` and `trees/` (MEASURED).
